# ClickIt — Product Guidelines

## Tone & Voice
**Professional and precise.** UI copy and documentation should be
direct and technical. No filler words, no marketing fluff.
Power users read to act, not to be entertained.

## Error & Permission Communication
**Direct and actionable.** When something fails, say what failed
and exactly what the user must do to fix it. Avoid vague messages
like "something went wrong." Prefer: "Accessibility permission
required — open System Settings > Privacy & Security."

## Visual & UI Principles
**Native macOS first.** Follow Apple Human Interface Guidelines.
Use system controls, system fonts, and standard macOS patterns.
No custom chrome, no skeuomorphic design. The app should feel
like it belongs on macOS, not like it was ported from another platform.

## Feature Scope (Stabilization Phase)
**Selective additions only.** New features must demonstrably reduce
user friction or fix a real pain point. Default answer to "should
we add this?" is no. Prefer polishing what exists over building
what's new.

## Pro vs Lite Priority
**Lite is the primary product.** ClickIt Lite is the focus for
new work, polish, and bug fixes. ClickIt Pro is maintained but
not the primary development target. Features ship to Lite first.
